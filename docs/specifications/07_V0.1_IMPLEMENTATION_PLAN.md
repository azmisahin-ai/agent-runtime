# 07 — V0.1 Implementation Plan

**Status:** NORMATIVE implementation plan

## 1. Objective

Turn specifications 01–17 into an executable, testable model-agnostic runtime. This document defines implementation boundaries; 18 is the master delivery order.

## 2. V0.1 scope

Required: TypeScript/Node runtime, SQLite persistence, domain model, event store, state machine, config/policy, Task/Attempt lifecycle, checkpoints, backend abstraction + Ollama, tool engine, context engine, memory, repository intelligence, verification, recovery, observability, API and evaluation.

## 3. Non-goals

Full autonomous deployment, distributed execution, advanced multi-agent orchestration, automatic continual learning, production vector optimization and simultaneous multi-agent production execution.

## 4. Repository layout

```text
src/
  domain application runtime persistence events config policy
  context memory repository tools backends verification recovery
  evaluation observability api
migrations/
tests/
  unit integration adversarial recovery evaluation e2e
docs/
```

## 5. Core domain

Project, Task, Attempt, Session, Event, Checkpoint, ContextSnapshot, Memory, ToolRun, VerificationResult, EvaluationRun and ConfigSnapshot.

## 6. Persistence

SQLite canonical store, WAL, foreign keys, migrations, repositories and transaction manager. State changes and canonical events must be atomic.

## 7. State machine

Centralize transition rules. API/services may request transitions but cannot directly mutate task state. Terminal states require a new attempt for recovery.

## 8. Vertical slice M1

Project creation → task creation → persistence → queue/run → baseline context → Ollama → read/search tools → observation → verification → checkpoint → event log → restart/resume → completed/failed → evaluation record.

## 9. Testing pyramid

Unit tests for domain contracts; integration tests for persistence/tool/backend boundaries; adversarial tests for security and invariant violations; recovery tests; evaluation tests; end-to-end vertical slice.

## 10. Definition of Done

No silent state transitions, no unverified success, no unauthorized tools, restart/resume works, canonical evidence persists, tests/build pass, roadmap/status/traceability updated.
